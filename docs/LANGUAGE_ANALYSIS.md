# C14 output-level language analysis

This is a new dossier reference implementation of the local analyser requested by the C14 first-deliverable specification. Original C14 implementation source was not recovered. It reuses the existing Unicode tokenizer, fixed-window MATTR, sample coefficient of variation and base-2 Jensen–Shannon functions from `packages/lab/analytics.mjs`.

`analyseLanguageWindow` accepts identity, arm, topic, task, participant kind and explicitly annotated segments. Authored text, quotations and required technical terms have separate token counts. Quotations require a source annotation; the analyser does not independently verify that source or automatically identify technical terms. Synthetic, model and human descriptors stay explicit and cannot be pooled across participant kinds.

Measurement uses a fixed number of authored words. A shorter sample returns `INSUFFICIENT_AUTHORED_TOKENS` and null metrics. MATTR uses pooled authored tokens with a declared window. Repeated trigrams are counted within each retained authored segment; removing a quotation cannot create a phrase across its boundaries. Sentence-length variation includes only complete sentences whose terminal punctuation is within the retained prefix. Abbreviations are not modeled. Truncation and segment counts remain inspectable.

`compareLanguageWindows` requires distinct record IDs, ready samples, equal sample sizes and MATTR windows, and matching topic/task/participant-kind labels. It recomputes MATTR from sampled words and rejects inconsistent token totals or malformed samples. Jensen–Shannon divergence uses a sorted union of observed authored-word support. Caller labels control eligibility; they do not prove semantic topic equivalence. No metric establishes cognitive capacity, semantic noninferiority, clinical effects or communication transfer.

The [frozen protocol](../experiments/language/protocol.json) uses 32 authored words and an eight-word MATTR window. Three positions and three labelled word patterns yield a deterministic trajectory demonstration. These patterns are authored synthetic inputs, not generated model outputs or the original Headspace simulator. Four recorded configurations retain 12 comparison attempts: six eligible, three with deliberate topic mismatch and three with insufficient authored words. All ineligible comparisons retain null derived values. Every run reproduced exactly.

The current public suite has 40 passing tests, including 16 focused analyser tests. [Coverage](../experiments/language/coverage.json) maps all four C14 IDs to their bounded checks and exclusions. The first focused and full-suite runs each failed one strict floating-point equality assertion: calculated MATTR was 0.8333333333333333 while the independent fraction 5/6 rounded to 0.8333333333333334. A tolerance of 1e-12 resolves numerical representation without changing the metric. Those failures and the previous 24-test receipt remain under `experiments/language/history`.

Reproduce with `npm test`, then `npm run measure:language`. Run `npm run build` and `npm run preview` to open C14's Lab tab. Browser controls change sample size, MATTR window and candidate pattern; buttons demonstrate topic rejection and insufficient samples. Export includes labelled synthetic input and every metric. Static builds copy frozen results and do not dispatch a model.

The [native source receipt](../experiments/language/native/receipt.json) binds two parent-integrated source proposals. Structural/schema/anchor/GTFL validation is separate from host behavioral tests and UI integration. General independent semantic validation remains unavailable. Semantic alignment, held-out transfer, human rater agreement, human outcomes and all hosted model measurements remain null. The broader longitudinal Headspace hypothesis remains untested.
